# Glossary Sources

墨声的金融词库不是一次性写死的完整数据库，而是一个可维护的 seed。扩展时优先参考公开、稳定、可解释的术语来源，再按中文语音输入场景筛选。

## Source Types

- 交易所与监管机构：适合上市、证券、披露、交易制度、产品定义。
- 投资者教育词库：适合股票、基金、债券、期权、交易基础概念。
- 投行/估值培训资料：适合 DCF、WACC、EV/EBITDA、LBO、可比公司法、可比交易法。
- PE/VC 术语表：适合 IRR、MOIC、DPI、TVPI、carry、capital call、dry powder。
- 灰度用户真实错误样本：最高优先级，因为它直接来自 ASR 和用户语境。

## Reference Examples

- Nasdaq Glossary：美股、交易、投资产品、市场术语。
- SEC Investor.gov Glossary：证券、基金、债券、期权、交易制度。
- HKEX / 港交所公开资料：港股上市、H 股、红筹、发售、配售、交易机制。
- CFI / Wall Street Prep：估值、投行、财务建模、PE 指标。
- FIBO：更重的金融本体，适合后续做大规模专业版词库，不适合 alpha 阶段直接全量引入。

## Selection Rules

1. `canonical` 放标准写法，优先使用用户自然会输入的写法。
2. `aliases` 放同义词、英文名、缩写、监管或交易所常用写法，只进入 LLM prompt。
3. `wrong_asr` 放语音识别常见错写，必须能解释为什么容易错。
4. `local_replace=true` 只给高置信错写，避免把用户说对的话改错。
5. 不要把普通词硬替换成专业词。例如“上市”不硬替换成 IPO，“可比公司”不硬替换成可比公司法。
6. 优先覆盖用户高频场景：口述微信/飞书、写邮件、写 memo、做会议纪要、写客户反馈。

## Feedback Format

灰度用户报错时，最好记录：

```text
原始 ASR：
用户想要：
使用场景：
是否可本地硬替换：
备注：
```

例子：

```text
原始 ASR：这次港交索递标以后还没过聆训
用户想要：这次港交所递表以后还没过聆讯
使用场景：港股 IPO 项目进展
是否可本地硬替换：港交索 -> 港交所 可以；递标 -> 递表 暂不硬替换；聆训 -> 聆讯 暂不硬替换
备注：递表/聆讯需要上市语境，先交给 LLM 判断
```
